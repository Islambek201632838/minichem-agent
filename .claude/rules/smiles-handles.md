# Verbatim SMILES: the handle protocol (minichem/molecules.py)

Goal (paper rule): the LLM never retypes a SMILES. Implementation:
1. **Registry** `state["molecules"]`: canonical SMILES, session-persistent. Handle `Mk` = `registry[k-1]`. `register()` dedupes by canonical form and stores canonical text.
2. **Supervisor sees no SMILES.** `render_context` shows `Mk: <formula>`; `mask_smiles` hides registered molecules (any spelling of the same molecule) in the conversation history and in sub-agent notes. The supervisor writes `Mk` in tasks and answers.
3. **Sub-agents see handles too (`minichem/handles.py`, since 2026-11-12).** The task keeps `Mk`; `HandleMiddleware` (passed to `create_agent`; the run's `RunHandles` travel as `context=`) resolves handles in the arguments `smiles`, `smiles_list`, `query`, `candidates` to the exact registry string BEFORE the tool runs, for local and MCP tools alike, and rewrites the ToolMessage the model reads so registered molecules appear as handles (`smiles` key becomes `id`; whole-string values such as `input`, `query`, `unresolved` items are replaced too). A molecule seen for the first time gets the next handle immediately (`RunHandles.registry` grows; `RunHandles.produced` feeds `turn_molecules`). The final answer is expanded by code (`expand_handles`, backticked).
4. **The tracer sits inside the tool call**, so `logs/trace.jsonl`, `ChatResult.tool_calls` and `ChatResult.routes` keep real SMILES (the UI draws routes from them); only what the model reads is rewritten.
5. **Guards:** `unverified_smiles` flags structural-looking valid SMILES in the final answer that are not in the registry (appended as a Warning). `_raw_arguments` (agents/base.py) flags every SMILES the model wrote into a molecule argument instead of a handle, except one the user typed in the current question; surfaced as `ChatResult.warnings` and a trace step. An unknown handle (`M9`) passes through unchanged and the tool answers "Invalid SMILES".

Known limits (documented in README): the model can still write a SMILES from its own knowledge into an argument (flagged, not blocked); the supervisor can still emit a correct SMILES from its own knowledge if it matches the registry. Rejected alternatives: a custom wrapper around every tool (double tracer events, MCP tools are built by a library), a contextvar for the handle table (implicit state; `context=` is explicit and tested), and changing the MCP server schemas (the servers stay usable by other clients that pass real SMILES).

Tokenizer notes: `_clean` strips prose punctuation and wrapping parentheses in a loop (bug history: a SMILES written as ``(`CC(C)...`)`` used to be missed by both detector and guard). User-SMILES detection accepts tokens with structural characters or all-caps atom strings (`CCO`); the guard requires structural characters to avoid flagging acronyms.
